## 3. 1호기 출고 1건 — PLC 담당자 동석 (핵심, 20분)

담당자가 XG5000 에 **M785**(1호기 Unload Complete)와 **M1538**(그 Ack)을 띄운 상태에서 1호기 출고를 1건 보낸다.
크레인이 104 에 내려놓는 순간부터 이 순서가 몇 초 안에 지나가야 한다.

```
M785 ↑ (크레인: 내려놨다)
  → 0.3초 안  M1538 ↑ (WCS)      wcs_log_pgr : [VEH_SC] VEHICLE@11 UNLOAD_COMPLETE_ACK (M1538) ON 기록
  → M785 ↓ (크레인: 확인했다)
  → M1538 ↓ (WCS)                               ... OFF 기록
  → C/V#2 벨트 기동 104 → 103
```

| 보이는 것 | 뜻 | 다음 |
|---|---|---|
| **A** `ON 기록` → 몇 초 안 `OFF 기록`, **벨트가 돈다** | 원인은 지워지던 Ack 였다 | 끝. 출고 몇 건 더 돌려 재현 없음을 본다 |
| **B** `ON 재기록 - 외부 덮어쓰기 의심` 이 반복 | 우리가 올리는 족족 누군가 내린다 (공통 알람은 껐음) | 담당자: "M1538 을 리셋하는 래더가 있습니까?" |
| **C** `ON`→`OFF` 깨끗한데 **벨트가 안 돈다** | 크레인 핸드셰이크는 끝났고 벨트가 다른 것을 기다린다 | 담당자: "C/V#2 가 기동하는 조건이 정확히 무엇입니까?" C/V 쪽 Load Complete #2 Ack 로그와 대조 |

**또 104 에서 멈추면**
- **M785 가 ON** 이면 1초만 기다린다 — WCS 가 스스로 다시 쓴다(재기록 로그). 그래도 안 돌면 **S/C#1 상태창 → [확대] → 하역ACK 옆 [쓰기] → [예]** (Ack 를 크레인 스레드가 정식 경로로 다시 쓴다). 그래도면 담당자가 M1538 을 강제 ON 하고 위 순서가 이어지는지 본다.
- **M785 가 OFF** 면 Ack 를 켜도 의미가 없다. 담당자가 포트 인수 절차를 다시 태우거나 벨트를 수동으로 104→103 보낸다. **ECS 는 손댈 것 없다** — 화물이 103 에 닿으면 RGV 가 자동으로 나간다.

**로그 뽑기**
```sql
SELECT ins_dt, pgr_nm, log_kor FROM wcs_log_pgr
 WHERE ins_dt >= '2026-09-15'
   AND (log_kor LIKE '%VEHICLE@11%'
     OR (log_kor LIKE '%방향지시%' AND log_kor LIKE '%[[]10[34]]%')          -- C/V#2 방향 (트랙 103/104)
     OR log_kor LIKE '%→ %MX129[6-9]%' OR log_kor LIKE '%→ %MX130_%' OR log_kor LIKE '%→ %MX131[01]%')  -- C/V#2 Ack 비트 1296~1311
   -- 09-15 정정 : '%Load Complete #2%' 로 걸면 모든 C/V 의 2번 신호가 잡혀 다른 컨베이어 줄이 쏟아진다. C/V#2 는 Ack 비트 %MX1296~1311, 방향은 트랙 103/104 로 거른다.
 ORDER BY ins_dt
```

### 왜 1호기만 멈추는가 — PLC 조사본(260818) 근거

PLC 담당자 조사본 2장 제목이 **"S/C #1 Alarm 보고"** 다. 1호기가 `M0492`(%MX786)를 켜면 ECS 가 `M0963`(%MX1539)으로, `M0493`(%MX787)에는 `M0964`(%MX1540)로 답한다. 3~6장은 2~5호기에 각자 다른 주소를 준다(2호기 `M0512`/`M0973` …).

1호기 응답 워드 `M096x`(%MX1536~1551) 한 칸에 이 비트들이 같이 들어 있다.

| 구표기 | 실주소 | 신호 | 쓰는 곳 |
|---|---|---|---|
| M0960 | %MX1536 | 이송지시 | 크레인 스레드 |
| M0961 | %MX1537 | 적재완료 Ack | 크레인 스레드 |
| **M0962** | **%MX1538** | **하역완료 Ack (오늘 보는 비트)** | 크레인 스레드 |
| M0963 | %MX1539 | 알람 발생 Ack | 크레인 스레드 + 옛 "공통 알람" 루틴 |
| M0964 | %MX1540 | 알람 해제 Ack | 크레인 스레드 + 옛 "공통 알람" 루틴 |

- 2~5호기도 워드 구성은 같다. **다른 점은 1호기 워드만 두 곳에서 쓴다는 것**이다. 옛 루틴이 조사본 2장의 1호기 주소를 전 설비 공통 알람으로 잘못 박아 두었다.
- 두 곳 모두 `WCS_TASK_CV` 안이고, 비트 하나를 **워드 전체 읽기 → 비트 수정 → 워드 쓰기**로 쓴다. 한쪽이 먼저 읽어 둔 낡은 워드를 되쓰면 방금 올린 M0962 가 다시 0 이 된다. IO_TASK 는 PLC 에 쓰지 않는다.
- **09-14 배포본부터 비트 쓰기를 구 ECS 와 같은 단일 비트 쓰기(`%MX`)로 바꿨다.** PLC 가 그 비트 하나만 바꾸므로 같은 워드를 여러 곳이 써도 서로 지우지 않는다. 시뮬 체인에서 Ack · 이송지시가 새 방식으로 정상 동작했다.
- **문서와 구 ECS 는 잘못이 없다.** 한 워드에 이송지시·적재 Ack·하역 Ack·알람발생 Ack·알람해제 Ack 가 같이 있는 것은 5대 모두 같은 설계다(메모리 맵 = 구 ECS 관측표 1호기 B0603, 2호기 B0613, 3호기 B0623 …). 구 ECS 는 단일 비트 쓰기라 같은 워드여도 서로 지우지 않았다. 1호기만 난 것은 새 WCS 가 시나리오 7장(1호기 주소로 그린 알람 예)을 "전 설비 공통 알람" 고정 주소 루틴으로 넣어, 1호기 워드만 두 스레드가 워드 단위로 되썼기 때문이다. 두 가지 모두 09-14 배포본에서 고쳤다(루틴 끔 + 단일 비트 쓰기).
- 이번 배포본은 이 루틴을 끈다(2번의 `사용 안 함` 줄). 그래서 오늘 **B**(재기록 반복)가 나오면 우리 쪽이 아니라 래더 등 다른 곳을 봐야 한다.
- 조사본에 **없는 것**: 크레인 반송 핸드셰이크(`M0491` 하역완료 · `M0962` Ack)와 1호기가 쓰는 C/V#2 시나리오. 위 설명은 "같은 워드에 두 곳이 쓴다"까지이고, 실제로 지워졌는지는 오늘 로그로 가린다.

## 7. PLC 담당자께 묶어서 물어볼 것

- **M1538**(1호기 Unload Complete Ack)을 **리셋하는 래더**가 있는가 — 있다면 어떤 조건에서
- **C/V#2 벨트가 104→103 으로 기동하는 조건**은 정확히 무엇인가 (방향 외에 크레인 Ack / Load Complete #2 Ack 를 보는가)
- 크레인이 Unload Complete 를 올리고 **Ack 를 기다리는 시간**(타임아웃)이 있는가, 넘기면 어떻게 되는가
- 완료 이벤트는 **Ack 받을 때까지 유지**되는가, 정해진 펄스 폭인가 (폴링이 놓칠 수 있는 쪽이면 래치 협의)
- RTV 알람 해제 시 **D211**(ALARM_SET_CODE)을 0 으로 내리는가
- (한 줄만) D301 에 넣는 값은 문자 `'1'`(0x31)이 맞는가
- **1호기 응답 워드(M0960~M096F)** 를 래더가 **워드 단위로 통째로 쓰는 곳**이 있는가 (오늘 B 가 나오면 이것부터)
- **조사본(260818) 오기 확인** — 프로그램은 구 ECS 운영 정의대로 정정한 값으로 돈다. 맞는지 한 번에 확인받는다.

  | 구간 | 조사본 | 프로그램(정정값) |
  |---|---|---|
  | 출고 RGV 픽업 이벤트 | `M0202` `M0242` `M0282` `M0322` | `M0201` `M0241` `M0281` `M0321` (C/V#3·5·7·9) |
  | 입고 RGV 하역 Ack | `M0831` `M0851` `M0871` `M0891` | `M0832` `M0852` `M0872` `M0892` (C/V#4·6·8·10) |
