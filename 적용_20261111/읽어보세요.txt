[TASK\HOST_TASK]  TASK_LFC10_G1_ECSCOM.exe  빌드 2026-11-11 (빌드 시각은 보고서 [시스템] 에도 찍힌다)
  1) 접속이 쌓이는 문제 : 수신 소켓에 연결 유지 확인(TCP keep-alive, 기본 60초)을 걸었다. 상대가 FIN 없이 사라져도 접속 스레드가 스스로 끝난다.
     접속이 끝나면 그 접속의 DB 개체를 반납한다 - 시험(40접속 열고 닫기) 핸들 +209 → +4, 메모리 누적 멈춤.
  2) 화면 갱신 : 작업 스레드가 화면 목록(ListView)·신호등 이미지를 직접 만지던 것을 화면 스레드로 넘겼다(화면이 밀리면 화면 줄만 버린다).
     작업 스레드가 쉬면서 화면 이벤트를 처리하던 것(DoEvents)도 화면 스레드에서만 하게 했다.
  3) 죽었을 때의 기록(msjexhnd 와 같은 쓰임) - 실행 폴더에 생긴다 :
     CrashReport\HOST_<시각>_FATAL.txt / .dmp   처리되지 않은 예외 : 예외 종류·호출 경로·자원·접속 상태·최근 로그 300줄·모듈 + 덤프
     CrashReport\HOST_<시각>_UI.txt             화면 스레드 예외 : 창 없이 보고서만 남기고 계속 돈다(종전엔 "처리되지 않은 예외" 창이 떴다)
     CrashReport\HOST_<시각>_HANDLED_<이름>.txt  SafeRun 이 삼킨 스레드 예외(그 스레드만 끝난 것 - 수신 접속 스레드면 통신이 멈춘다)
     CrashReport\HOST_<시각>_PrevAbnormalExit.txt  직전 실행이 정상 종료가 아니었을 때(스택 오버플로·강제 종료·정전 포함) 다음 기동 때 남긴다
     ECSCOMALog\Health_yyyyMMdd.log             1분마다 스레드·핸들·메모리·접속 수/상대 (접속이 쌓이는지 추세로 본다)
     죽으면 CrashReport 폴더와 Health 로그를 통째로 보내 달라고 하면 된다.
     화면 위쪽 [죽기 시험] 단추(INI 열기 왼쪽) : 확인 뒤 일부러 죽어 위 보고서/덤프가 남는지 확인한다. 숨기려면 [Crash] TEST_BUTTON=0.
     (시험하면 통신이 끊기고 프로그램이 종료된다 - 현장에서는 점검 시간에만 누른다)
  4) (선택) TASK\HOST_TASK\WER_LocalDumps_HOST_TASK.reg : 스택 오버플로 같은 .NET 이 가로채지 못하는 오류의 덤프는 Windows 가 남긴다.
     C:\ECS_Dumps 폴더를 만들고 관리자 권한으로 한 번 더블클릭해 등록한다.
